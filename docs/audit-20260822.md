# FreeInference Companion — Audit (2026-08-22)

Scope: does the plugin do what it says, does it stay invisible when it should,
is it properly isolated from the host client and other providers, and are the
diagnosis / cost-reduction features real. Cross-referenced against
anthropics/claude-code and openai/codex via DeepWiki.

## Evidence baseline

- `go build ./...` clean, `go vet ./...` clean, `gofmt` clean.
- `go test ./...`: 2 failures, both test-harness issues (see P2), all core
  packages (runtime, engine, state, schema, adapters, api) pass including
  `TestSecretNeverPersistsOrRenders`.

## What checks out (verified against code + upstream docs)

1. **Activation gating is real and strict.** `internal/runtime/activation.go`
   requires endpoint+credential from the approved `freeinference.org` host set,
   rejects conflicting runtime endpoints (`ANTHROPIC_BASE_URL` vs
   `OPENAI_BASE_URL` vs `FREEINFERENCE_BASE_URL` disagreement → inactive),
   treats non-FI hosts as conflict (no credential routing off-host), evaluates
   once per process, fingerprints credentials with salted HMAC for identity.
   `FI_PROVIDER` is attribution-only as documented.
2. **Hooks fail open correctly.** Both `run-hook.sh` scripts always exit 0;
   `runHook` gates on activation BEFORE any disk IO (no cache dirs, locks, or
   index entries in non-FI sessions). Unknown clients/events return silently.
   This matches the Claude Code hook contract (exit 0 = success, stdout JSON).
3. **Hook events match upstream.** Claude Code plugin declares
   SessionStart/SessionEnd/UserPromptSubmit/PreCompact/PostCompact/Stop/
   StopFailure — all supported by anthropics/claude-code (StopFailure fires on
   API-error turn ends; PreCompact exists though rarely shown in examples).
   Codex plugin omits StopFailure (correct: codex-rs HookEventName enum has no
   StopFailure) and uses PLUGIN_ROOT which Codex sets (with
   CLAUDE_PLUGIN_ROOT compat). Codex docs claim matches the enum exactly.
4. **Zero-byte invisibility contract.** 7-gate SurfaceEligibility
   (`Visible()`) requires runtime active + provider confirmed FI + session +
   activation identity match; wrapper emits zero bytes when fi produces no
   output (P0-3 verified in generated wrapper on this machine).
5. **Warning channel is correct.** Only `systemMessage` in JSON output
   (pkg/schema/telemetry.go); no additionalContext injection into model context
   anywhere outside tests. Matches Claude Code's documented hook JSON fields.
6. **Credential hygiene.** Key lives only in-memory per request, never
   persisted; allowlist construction for reports; redactor for key shapes;
   state files 0600/dirs 0700; session dir names SHA-256 hashed; path-shaped
   hook inputs never persisted. Regression-guarded by security_test.go (passes).
7. **Statusline composition.** Ownership by exact value equality, drift refusal,
   pre-install value preserved and restored on uninstall, transactional write
   w/ rollback, mode preserved. The installed wrapper on this machine behaves
   as documented.

## Findings

### P1 — should fix before wider release

**P1-1. `freeinference companion disable` marker file is dead code.**
`companion.go` writes `.companion-disabled` and `isCompanionDisabled()` reads
it — but nothing in the hook path, status path, or activation ever consults it
(grep confirms: only companion.go references it). A user who runs
`freeinference companion disable` gets a confirmation message, but hooks keep
running and surfaces keep rendering until they also export FI_DISABLED=1 (the
message hints at this, weakly). Either wire the marker into
`runtime.Evaluate()` (read via config dir at evaluate time) or make the
command print "hooks will continue until you set FI_DISABLED=1". This directly
undermines your "does not appear when it shouldn't" requirement: today there
is no persistent off switch that actually reaches the hooks.

**P1-2. Installed statusline wrapper points at a go-build cache temp binary.**
The wrapper on THIS machine (`~/.claude/statusline-freeinference.sh`) records
`~/.cache/go-build/cc/…-d/fi` as its preferred binary — a `go run` artifact
that the Go build cache can garbage-collect at any time. After GC the wrapper
silently falls back to PATH (`fi`, not even `freeinference`) and then to
nothing. Two fixes: (a) installer should refuse to record binaries under
go-build/temp paths, and (b) the fallback chain should try
`~/.local/bin/freeinference` too, matching what run-hook.sh does. Also note
this machine's wrapper was generated by an older build that used binary name
`fi` — reinstalling with the current CLI regenerates it, but existing users of
old builds carry stale wrappers forever since there is no migration check.

**P1-3. Version-consistency test references a manifest that doesn't exist.**
`internal/cli/version_test.go` lists `../../plugin.json` (repo root) among the
manifests; no such file is committed. Test fails for every fresh clone,
which trains developers to ignore red tests (and CI may be running with this
masked). Delete the entry or restore a root manifest.

### P2 — correctness / polish

**P2-1. `plugins/smoke_test.go` TestClaudeCodeBundledBinaryRuns requires
`plugins/*/bin/` to exist in a source checkout.** Those directories are
release-time artifacts (Makefile creates them during `package`). Fresh-clone
`make test` fails. Guard the test with an existence skip when bin/ is absent
(when present, still verify).

**P2-2. README says release binary "verified with ldd" but Makefile P2-45
switched to portable `file` static-check.** Minor doc drift; align wording.

**P2-3. Codex SKILL.md documents `$freeinference-*` skill invocations while
Claude Code SKILL.md documents plain commands — fine, but neither mentions
that warnings only fire on UserPromptSubmit. Users reading the skill won't
know why nothing appears between prompts. One sentence fixes it.

**P2-4. `docs/codex.md` says Codex asks users to approve plugin-local hooks
"on installations that support plugin-local hooks" — hedged correctly, but the
hooks.json uses `${PLUGIN_ROOT}` unquoted inside a JSON string command that
the script then re-expands; verify against the installed Codex version that
hook commands support variable interpolation in that position (DeepWiki
confirms PLUGIN_ROOT is exported to the hook process environment, so the
safer form is invoking the script via the env var at shell level, e.g.
`"$PLUGIN_ROOT/scripts/run-hook.sh"` — which is what you already do; just make
sure the JSON-declared string survives any TOML/JSON schema validation Codex
runs at load time; unsupported events are silently ignored by some versions,
which is acceptable here).

### P3 — isolation hardening (matches your "not isolated enough" concern)

**P3-1. Hook stdin is parsed but its size is unbounded before parse.**
`ParseHookInput` reads the full stdin body. Claude Code/Codex payloads are
small, but a malformed or hostile caller can pipe gigabytes. Wrap stdin in an
`io.LimitReader` (e.g. 1 MiB) before json.Decode. Same class as the response
bounds you already apply in api/client.go.

**P3-2. Session-state namespace is unnamespaced by design ("sessions are
independent of provider") — meaning a session recorded against endpoint A
remains visible if the user switches to endpoint B mid-directory. Eligibility
gating hides cross-provider leakage at render time (activation ID must match),
but `freeinference sessions` lists across identities. Consider labeling each
index row with the identity DirName and filtering by current identity unless
`--all-identities` is passed.

**P3-3. `FI_UNSAFE_FORCE_ACTIVATION=1` activates with origin
`unsafe://force-activation` and Active=true — downstream ManagementBaseURL()
guards it, good — but any code path comparing Origin strings to real hosts
should be greped periodically; consider making UnsafeForced also force
Disabled=true semantics for network workers rather than relying on each call
site remembering to check.

**P3-4. The salt loader creates the salt lazily with 0600 — confirm the parent
dir is created 0700 as well (secure.go handles files; verify directory perms
on first-run creation path).

## Feature goals assessment (diagnosis + cost reduction)

What you wanted vs what exists:

| Goal | Status |
|---|---|
| Help FreeInference diagnose their infra | Partial: `doctor` (endpoint/auth/catalog/model-access checks), optional manual synthetic probe marked X-Probe, sanitized `report` for sharing. No automated telemetry leaves the machine — by design. If FreeInference wants diagnosis data, `report --format json` is the vehicle; consider adding a `report --redact-level minimal` tier so users can share more signal with less friction. |
| Users mindful of own limits | Yes, genuinely: context pressure tiers, budget projection tiers (healthy/watch/low/critical), projection confidence capped at medium honestly. Account usage is null until FreeInference exposes an endpoint — README is honest about this. |
| Materially reduce FI cost client-side | Partial: cache-low warning WITH root-cause attribution (thrashing/no-caching/decay/intermittent), TTL warm-up suggestion, projection overflow warning. These are the right levers (cache reads are the cost driver). Missing: nothing suggests concrete fixes for "Thrashing" (e.g. move dynamic content after breakpoints) — add one-line remediation text per pattern; and nothing nudges users toward smaller small-fast models. |

## Verdict

Core claims hold up: activation gating, fail-open hooks, zero-byte
invisibility, credential hygiene, and honest null-vs-zero semantics are all
real and tested. The two things most aligned with your stated worries — a
working kill-switch (P1-1) and stale-wrapper robustness (P1-2) — are the gaps.
Fix those plus the two broken tests and the isolation items P3-1/P3-2 and this
is solid.
